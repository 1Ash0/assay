### `gen_ai.conversation.compacted` — the key finding for gap 7

**`gen_ai.conversation.compacted` exists in the spec** as a boolean `Recommended` attribute on Anthropic inference spans. From the spec footnote: "This attribute is a positive indicator of context compaction. Instrumentations SHOULD set it to `true` only when they can reliably determine that context compaction was applied. Instrumentations SHOULD NOT set it to `false`; they SHOULD leave it unset otherwise."

**What is NOT in the spec:**
- No `compact` operation type in `gen_ai.operation.name` (values are: chat, create_agent, execute_tool, invoke_agent, invoke_workflow, plan, retrieval, create_memory, etc.)
- No compaction span (no span for the compaction event itself, only a boolean flag on an inference span)
- No compaction metadata attributes (no pre_tokens, post_tokens, dropped_tokens, duration_ms)
- No subagent lifecycle spans (`subagent_start`, `subagent_stop`) specific to Claude Code's model
- No context-composition breakdown (System / CLAUDE.md / tools / history / etc.)

**CORRECTION vs earlier notebook entry.** Skill spans DO exist in the spec. `gen-ai-agent-spans.md` (172 KB, fully parsed in E6 below) contains a `Load skill span` refinement (`gen_ai.execute_tool.load_skill.internal`) with attributes: `gen_ai.skill.name`, `gen_ai.skill.description`, `gen_ai.skill.source.uri`. Frameworks targeted: Google ADK, OpenAI Agents, Strands, Agno. There is ALSO a `Read skill resource span`. So skills are covered at the spec level. The gap is that Claude Code's current OTel instrumentation does not set `gen_ai.skill.name` when the Skill tool is called — an instrumentation gap, not a spec gap.

**Gap 7 finding (refined):** `[read]` Compaction exists only as a boolean flag (`gen_ai.conversation.compacted`), not as a structural entity with rich metadata. No operation type for compaction. No context-composition breakdown. These remain upstream-proposal opportunities. The skill gap is actually an instrumentation gap in Claude Code, not a missing spec entity.

## C — context-analyzer / context-tracker (source read)

**Source:** `manavgup/context-analyzer` README.md at source (raw GitHub). v1.0.0, MIT, PyPI: `context-tracker`. `read`

### Architecture

```
Claude Code Hooks → ~/.claude/context-trace/<session_id>.jsonl
Transcripts → ~/.claude/projects/<project>/<session_id>.jsonl
  ↓
SQLite
  ├── sessions, api_calls, blocks, turns
  ├── hook_events, subagents, subagent_api_calls
  └── tool_result_offloads
  ↓
FastAPI dashboard (localhost:8080) + MCP server
```

**Hooks registered:** PostToolUse, PostToolUseFailure, PreCompact, PostCompact, SessionStart, SessionEnd, UserPromptSubmit, SubagentStart, SubagentStop, InstructionsLoaded.

**What it captures:** L1 (JSONL transcripts) + L2 (hooks). No OTel (L3), no proxy / request bodies (L4). Token counts come from transcript API-reported values — API-level ground truth for usage, but no raw request body access. `read`

### Dashboard features (read from README screenshots and descriptions)

- Context growth chart with budget lines (200K/500K/700K/1M) and autocompact threshold marker
- Cache-read churn chart (per-call re-read cost)
- Composition donut: Tool I/O vs Conversation vs System prefix
- Message inspector with collapsible content
- Cross-session analytics: cost/call vs peak context scatter, session comparison bar chart
- Subagent per-call churn tracked

### Published metrics (claimed from own sessions, not independently verified by us)

- Cost per API call: 4.3× scaling from 63K to 721K peak context ($0.23 → $0.98/call)
- 30% of context becomes stale within 5 turns
- Tool I/O consumes 60%+ of used context
- Cache hit rate 96–98% when system prompt prefix is stable

All of these are `[read, single-author corpus]` — plausible, not independently verified. Label `[read-summary]` until we replicate on our own corpus.

### MAST-Data / MAD (mcemri/MAST-Data, HuggingFace) — `[read]`

Full schema read from HF viewer (not downloaded).

| Field | Type | Values |
|---|---|---|
| `mas_name` | string | AG2, MetaGPT, ChatDev, Magentic, AppWorld, HyperAgent, OpenManus (7) |
| `llm_name` | string | GPT-4o, Claude, GPT-4o-mini, Qwen, CodeLlama (5) |
| `benchmark_name` | string | ProgramDev, ProgramDev-v2, GSM, Olympiad, GAIA, MMLU, Test-C, SWE-Bench-Lite (8) |
| `trace_id` | int | index within (mas_name, llm_name, benchmark_name) config |
| `trace` | dict | `{key, index, trajectory}` — trajectory is a plain-text log string |
| `mast_annotation` | dict | 14 MAST codes → 0/1/null |

14 MAST failure codes in 3 groups:
- **Specification:** 1.1 Disobey Task, 1.2 Disobey Role, 1.3 Step Repetition, 1.4 Loss of History, 1.5 Unaware of Termination
- **Inter-Agent Misalignment:** 2.1 Conversation Reset, 2.2 Fail to Ask Clarification, 2.3 Task Derailment, 2.4 Information Withholding, 2.5 Ignored Agent Input, 2.6 Reasoning-Action Mismatch
- **Task Verification:** 3.1 Premature Termination, 3.2 No/Incomplete Verification, 3.3 Incorrect Verification

**Format:** trajectory is plain-text log (not OTel, not JSONL). NLP parsing needed to extract span-like structure.
**Access:** NOT gated. 1,642 traces, 202 MB. `MAD_full_dataset.json` + `MAD_human_labelled_dataset.json` (19 rows, inter-annotator study).
**Annotations:** LLM-annotated, not human. Human subset (19 rows) uses 4 different taxonomy revisions (18/17/17/14 modes) — codes not comparable across rounds.
**Citation:** NeurIPS 2025 (Cemri et al., Berkeley/MIT/UIUC/UCDavis team).
**Licence:** not stated on HF viewer page; check GitHub `mcemri/MAST` for details. `[unverified]` Treat as unknown until confirmed.

**Use for assay R3:** possible for testing failure-mode detectors (D5-D9 analogues) on a multi-agent corpus. Not OTel, so the OTel importer is not exercised by this dataset. A plain-text-trace importer would be needed.

### TRAIL (PatronusAI/TRAIL) — `[read]` 2026-10-31

**Access:** gated (Asmit approved 2026-10-31). Dataset `PatronusAI/TRAIL`, 148 traces (117 GAIA + 31 SWE-Bench), MIT licence. Splits: `gaia` (117 rows), `swe_bench` (31 rows). Two columns: `trace` (JSON string, 96k–9MB) and `labels` (JSON string, 492–17.6k chars).

**`trace` format:** `{trace_id, spans: [{span_id, parent_span_id, span_kind, resource_attributes, span_attributes, logs[], child_spans[]}]}`. Span attributes use OpenInference keys: `llm.input_messages.N.message.{content,role}`, `llm.token_count.*`, `openinference.span.kind`, Patronus SDK `pat.*` attributes. Roles observed: `assistant`, `tool-call`, `tool-response`. SWE-Bench row 0: smolagents CodeAct agent solving pylint-dev/astroid `Dict.getitem` bug using `python_interpreter` + `gitingest`.

**`labels` format — verified from swe_bench row 0 (trace_id 58bfe9dde723516f4d9366eb6b4b6388):**
```
{
  trace_id: string,
  errors: [{
    category: string,    // "Instruction Non-compliance" | "Incorrect Problem Identification" |
                         // "Language-only" | "Resource Exhaustion" | "Tool Output Misinterpretation" | ...
    location: string,    // span_id of the offending span
    evidence: string,    // verbatim excerpt
    description: string,
    impact: "LOW" | "MEDIUM" | "HIGH"
  }],
  scores: [{
    reliability_score: int (1–5),
    reliability_reasoning: string,
    security_score: int (1–5),
    security_reasoning: string,
    instruction_adherence_score: int (1–5),
    instruction_adherence_reasoning: string,
    plan_opt_score: int (1–5),
    plan_opt_reasoning: string,
    overall: float (1.0–5.0)
  }]
}
```
Row 0 has 6 errors (impacts LOW/MEDIUM/HIGH) and overall score 3.25/5. Labels are **human-annotated per trace** (not per span; `location` points to the relevant span). This is the highest-quality labelling of the three external datasets (MAST=LLM-annotated, AgentRx=human step-level failure, TRAIL=human trace-level error taxonomy + scores).

**Use for assay R3:** OTel-shaped traces from smolagents — directly exercises the OTel importer. Labels give ground-truth error categories + impact + scores to calibrate detector output. Not Claude Code transcripts. High priority for R3 corpus.
