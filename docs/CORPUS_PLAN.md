## Step 3 — more than one user (you find contributors, I build the intake)
- **What a contributor shares:** only core's redacted view of a session (`assay export-view <session.jsonl> --truth real --id <name>`), never the raw file. It is the same redaction the site uses and passes the same publish check.
- **What they also tell us:** OS, Claude Code version, plan, and which content flags were on. That goes on the card as `contributor`.
- **Gap on our side:** the site is built from raw sessions, so a redacted view cannot be added to it yet. Before the first contribution I add an intake that accepts views (`corpus add-view`) and runs the publish check on them. Aggregate results (R2, T3) need the raw files, so contributed sessions count for the site, the gates and the version census, but not for those studies unless a contributor runs the study scripts locally and sends the result JSON.
- **Target:** 2–3 contributors × 3 sessions each, on different machines.

## Step 5 — ground truth from L4 (you capture, I compare)
For every L4 session from step 2, `node scripts/l4-calibrate.mjs <session.jsonl> <raw-dir> <out.json>` compares each recorded request with its raw body: fields that agree, fields that differ, and in which direction. The comparisons go into one result across sessions (not one file per session), and R2's held-out set is extended with them. Today's result rests on 3 sessions. Ten would let us state the record-versus-wire differences with a count, not an anecdote.
